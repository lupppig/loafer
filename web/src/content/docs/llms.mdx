# LLM Setup

Loafer uses Large Language Models (LLMs) to perform AI-powered transformations during your ETL/ELT pipelines, and to execute `elt` strategies dynamically. We officially support four major LLM providers out-of-the-box:

- **Gemini** (Google)
- **OpenAI**
- **Claude** (Anthropic)
- **Qwen** (Alibaba)

To use AI transformations, you must provide your preferred LLM configuration in your pipeline's `llm` block.

---

## Configuration Overview

Configure the provider and authentication in your `pipeline.yaml`. The `model` field is optional:
when omitted, Loafer selects the provider-specific default listed below. Pin a model explicitly
when reproducibility across Loafer upgrades matters. Use environment variable substitution
(`${ENV_VAR}`) instead of hardcoding secrets.

```yaml
llm:
  provider: gemini
  api_key: ${GEMINI_API_KEY}
```

---

## Supported Providers

### 1. Gemini
Gemini is Loafer's default provider. The default model is `gemini-3.6-flash`.

**Configuration:**
```yaml
llm:
  provider: gemini
  model: gemini-3.6-flash
  api_key: ${GEMINI_API_KEY}
```

**Environment Setup:**
```bash
export GEMINI_API_KEY="your-gemini-api-key"
```

### 2. OpenAI
The default model is `gpt-5.6-terra`, selected to balance transformation quality and cost.

**Configuration:**
```yaml
llm:
  provider: openai
  model: gpt-5.6-terra
  api_key: ${OPENAI_API_KEY}
```

**Environment Setup:**
```bash
export OPENAI_API_KEY="your-openai-api-key"
```

### 3. Claude
The default model is `claude-sonnet-5`.

**Configuration:**
```yaml
llm:
  provider: claude
  model: claude-sonnet-5
  api_key: ${ANTHROPIC_API_KEY}
```

**Environment Setup:**
```bash
export ANTHROPIC_API_KEY="your-anthropic-api-key"
```

### 4. Qwen
The default model is `qwen3.7-plus`.

**Configuration:**
```yaml
llm:
  provider: qwen
  model: qwen3.7-plus
  api_key: ${QWEN_API_KEY}
```

**Environment Setup:**
```bash
export QWEN_API_KEY="your-qwen-api-key"
```

---

## Default Selection and Model Pins

Omit `model` to follow the default shipped with your installed Loafer version:

```yaml
llm:
  provider: claude
  api_key: ${ANTHROPIC_API_KEY}
```

For reproducible production pipelines, pin the tested provider-native model ID and review model
changes during Loafer upgrades.

## Security Best Practices
Never commit `pipeline.yaml` files with hardcoded API keys. Always use Loafer's built-in `${VAR_NAME}` syntax to securely source secrets at runtime.
