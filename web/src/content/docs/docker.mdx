# Docker
Last updated: March 2025  ·  3 min read  ·  [Edit on GitHub ↗](https://github.com/lupppig/loafer/edit/main/web/src/content/docs/docker.mdx)

Loafer's release image installs the checked-in production lock, runs as an unprivileged user, and
contains both the `loafer` CLI and `loaferd` control-plane entry points.

## Quick start

Pull and run a pipeline directly.

### 1. Pull the image
```bash
docker pull ghcr.io/lupppig/loafer:latest
```

### 2. Execute pipeline
Mount your current directory into the container to enable Loafer to read your config and write results:

```bash
docker run --rm -it \
  --user "$(id -u):$(id -g)" \
  -e HOME=/tmp \
  --env-file .env \
  -v $(pwd):/workspace \
  -w /workspace \
  ghcr.io/lupppig/loafer:0.5.0 \
  run pipeline.yaml --local
```

## docker-compose

The checked-in Compose `platform` profile runs PostgreSQL, one-shot metadata and object-storage
initialization, `loaferd`, one scheduler, and one durable worker. Copy `.env.example` to `.env`,
replace every placeholder, and pin `LOAFER_IMAGE` to the digest printed by the release workflow.
Edit `.env` before continuing.

```bash
cp .env.example .env
docker compose --env-file .env -f docker/docker-compose.yml config --quiet
docker compose --env-file .env -f docker/docker-compose.yml --profile platform up -d
```

Use the `daemon`, `scheduler`, or `worker` profile instead when deploying only that process role;
Compose still starts PostgreSQL and the required one-shot initialization dependencies.

`loaferd` binds only to `127.0.0.1:${LOAFERD_PORT:-9443}` on the host. Put a TLS reverse proxy on
that host port, strip client-supplied forwarding headers at the edge, and forward trusted
`X-Forwarded-Proto` and `X-Forwarded-For` values. Do not expose port 9443 directly.

The profiles drop Linux capabilities, prevent privilege escalation, use a read-only root
filesystem, persist PostgreSQL and Loafer object data, and wait for explicit initialization jobs
before starting services. They intentionally expect Better Auth/JWKS to be deployed separately.

## Environment variables in Docker

Never bake keys into the image. Restrict `.env` permissions for a single-host deployment and use a
secret manager for an orchestrated production deployment.
